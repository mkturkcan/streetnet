Data formats

Panorama index#

A Parquet or CSV table with one row per panorama (streetnet/index.py):

ColumnTypeRequiredMeaning
pano_idstringyesunique identifier
lat, lonfloatyescamera position, WGS 84
headingfloatyescompass bearing of the centre column of the panorama, degrees clockwise from north
pitch, rollfloatnocamera pitch and roll from the capture metadata in degrees, pitch 0 = level
nx, ny, nzfloatnoground up-normal in the camera frame (x right, y forward, z up); overrides pitch and roll
hfloatnocamera height above the ground in metres; 2.5 when missing
imagestringnopath of the panorama, absolute or relative to --images; <images>/<pano_id>.jpg when missing

Panoramas are equirectangular JPEGs (width = 2 x height) whose centre column looks along heading. Without pitch, roll or a normal the camera is treated as level. The map frame is the UTM zone that contains the median camera position.

Reference points#

streetnet eval --gt reads a Parquet or CSV table with one row per reference asset:

ColumnMeaning
gt_keyclass key of the map (tree, fire_hydrant, storm_drain, ...; see streetnet/configs/classes.json)
x, yposition in the map frame (UTM metres of the index's zone), or
lon, latposition in WGS 84, converted to the map frame

The classes present in both the map and the reference table are evaluated. The evaluation region is given by panoramas of the index (--region, a text file of pano ids; all panoramas by default) or by a table of disk centres with lon and lat (--region-centers); evaluation.md gives the protocol.

Run folder#

runs/city/
├── run.json                    views, threshold and vocabulary of the run; a later call with other settings stops
├── det/<pano_id>.parquet       detections of one panorama (below); written last, marks the panorama as done
├── raw/                        with --keep-raw: SAM 3 and Mask2Former records, label maps (PNG, Vistas ids)
├── logs/detect_<i>.log         one log per GPU process
└── map/
    ├── <name>_assets.parquet   the map (below)
    ├── <name>_assets.geojson   the same as GeoJSON points (id, class, support, confidence)
    ├── <name>_obs.parquet      the observations of each asset
    ├── <name>_panos.txt        the panoramas the map was built from
    └── <name>_summary.json     counts and settings

A detection file takes 33 KiB per panorama on average in the New York City run.

Map: map/<name>_assets.parquet#

The map stage writes the classes of the parameter file found in the detections: the 22 classes of the published map and utility poles, which serve as pole carriers for signs. The dataset export leaves utility poles out.

ColumnMeaning
asset_idrow number
labelclass key
x, y; lon, latposition in the UTM frame (metres) and in WGS 84
support, n_obsdistinct panoramas and observations in the cluster
score_mean, score_max, confmean and maximum detection score; confidence 1 - prod(1 - best score per panorama)
rng_min, rng_medsmallest and median horizontal range of the cluster's observations (m)
spreadmedian distance of the observations from the asset position (m)
best_obsthe observation with the smallest range, as an id local to its block
best_pano, best_rowthat observation's panorama and its row in the panorama's detection file
estimatordepth (MoGe-2 range) or ground (flat-ground geometry), the more frequent among the cluster's observations
block, densethe 1 km block that kept the asset; whether the block used the uncapped parameters
sourcethe model the class is taken from

<name>_obs.parquet lists the clustered observations: pano_id, row (row in the panorama's detection file), model, label, raw_label, score, view, box (x0, y0, x1, y1), X, Y (position in metres), rng, bearing, asset, loc_src (self or pole), loc_est (depth or ground), cut_bottom, cut_side and block.

The published dataset renames and reduces these columns:

Configuration#

FileContents
streetnet/configs/prompts.jsonthe vocabulary: per class, the SAM 3 prompts and the mount type
streetnet/configs/fusion_params.jsonper-class fusion parameters and the relabelling of pedestrian signals
streetnet/configs/classes.jsondisplay names, groups and colours of the published classes

A run can use another vocabulary (--vocabulary) and other fusion parameters (--params). The map stage leaves out classes without an entry in the parameter file and logs their names. The classes placed by range (DEPTH_CLASSES) and the pole carriers (POLE_CARRIERS) are set in streetnet/fusion.py. Parameters for a new city or camera rig should be tuned on reference data of that place.
